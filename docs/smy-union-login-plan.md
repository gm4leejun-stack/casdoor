# 萨摩耶联登与统一身份实施计划

状态：代码已按本计划实现，已完成模块、隔离数据库及构建验证；尚未部署或重启。真实浏览器端到端联调须在两端部署及配置后完成。接口与配置以 [联登接口说明](smy-union-login-api.md) 为准。

## 1. 目标与已确认规则

- 萨摩耶服务端调用 `POST /smy/unionLogin`，Casdoor 返回 `h5Url`；萨摩耶前端自动跳转，无需用户再点击。
- 跳转后自动完成 Casdoor 与 LobeHub 登录，直接进入 LobeHub 使用页面，不停留在登录、注册或首次引导页面。
- 固定组织 `beibei`，按萨摩耶 `uniqueId` 的绑定关系定位 Casdoor 用户。Casdoor 内部 `User.Id` 保持独立、稳定，继续用于 OIDC 身份。
- 已绑定时复用原用户；未绑定时创建 `normal-user` 普通账号，自动生成用户名，不设置密码，不填邮箱、手机号，不通过手机号复用其他账号。
- 联登手机号非必填，即使传入也不判断、不匹配、不更新；已有用户的联系方式保持原样。
- 已绑定用户禁用、删除或绑定异常时失败，不另建账号绕过限制。
- `h5Url` 有效期 5 分钟，成功兑换一次后失效；过期或已使用需要重新请求联登。
- 联登不查询订单、套餐、会员有效期或退款状态，不发放会员，不写会员有效期变化记录。
- 浏览器原有其他账号登录态时，最终登录本次 `uniqueId` 对应账号，不复用旧账号直接进入首页。
- 会员维护仍固定 `beibei/beibei-pro`，改为按 `uniqueId` 复用用户；原有月份计算、退款、幂等、锁、事务与操作档规则不变。

## 2. 修改范围

### 2.1 Casdoor：统一身份查找与建号

复用现有客户绑定表，不新增一套身份库：

1. 抽出联登和会员维护共用的 `uniqueId` 查找／建号逻辑。复用已有组织锁及用户行锁，账号和绑定在同一事务创建，避免并发创建两份用户。
2. 保持 `uniqueId` 唯一、用户绑定唯一。手机号退出身份约束，移除客户表手机号唯一索引，允许没有手机号的绑定；旧手机号仅作为历史资料保留。
3. 对现有绑定直接复用原 `User.Id`、用户名、订单和会员，不迁移用户、不按手机号重新绑定、不重写历史操作档。
4. 新账号显示名使用自动生成的普通显示名，不依赖手机号。
5. 联登创建的客户绑定保持会员操作序号为 0，不初始化操作档、不建立 Subscription。

### 2.2 Casdoor：会员维护适配

重点涉及现有 `object/smy_membership_store.go`、`object/smy_membership_ledger.go`、`object/smy_membership_guard.go`：

1. 会员维护按 `uniqueId` 查找客户及原用户，不再按手机号选择用户。新客户也通过共用逻辑创建无联系方式普通账号。
2. 会员通知中的手机号仍按该接口原有报文规范接收、留档，不用于身份匹配，不写入 Casdoor 用户手机号；不因手机号与以前不同而拒绝同一客户的续费、退款或重复通知。
3. 移除订单身份、快照和操作档重放中将手机号视为不变身份的检查，继续校验 `uniqueId`、订单归属、商品及原有业务条件。历史输入中的手机号原样保留。
4. 首次会员维护依据“尚未初始化会员操作档”判断是否初始化，不能再仅依据“刚创建客户绑定”。只有序号为 0 且没有操作档时允许首次初始化；其他序号／操作档异常继续失败。
5. 仅有联登绑定、不存在会员操作档的客户，不应被当成已托管会员；托管写保护以会员操作档已初始化为准。
6. 客服查询增加 `uniqueId` 精确查询及展示；手机号仅作历史查询线索，不再假设手机号唯一。同一手机号对应多个客户时明确返回可选择的客户，不任意取一条。
7. 未开通过会员的联登账号查询档案时显示“尚无会员操作档”，不把正常的零序号绑定误报为账实异常。

不更改自然月计算、退款扣减方式、重复订单终态、操作序号递增及全部业务写入同一事务的约定。

### 2.3 Casdoor：联登接口与一次性凭证

1. 新增 `POST /smy/unionLogin`，复用现有 2.0／3.1 公共协议、商户配置、验签和加解密实现。
2. 业务必填字段为 `uniqueId`；兼容省略 `userMd5Info`、空对象和携带 `mobile` 的旧请求。手机号内容不参与业务处理，公共签名仍覆盖原始报文。嵌套对象不能直接用现有仅接受字符串字段的 envelope 解析器解析。
3. 在事务内完成身份解析／建号及凭证持久化；提交成功后才返回含 `data.h5Url` 的签名／加密响应。失败不返回可用链接。
4. 新增最小的一次性凭证存储，绑定用户、目标应用、请求号、到期时间和兑换状态。使用不可猜测随机凭证，数据库存储凭证摘要，不把长期令牌或联系方式放在 URL。
5. 凭证签发时间起 5 分钟到期；兑换通过数据库原子条件更新／行锁实现单次成功，多个实例和并发兑换不能重复成功。
6. 联登请求实施签名报文防重放：校验请求时间有效窗口并记录请求号，重复请求不能反复生成新凭证。该窗口只用于联登，不改变会员接口延迟退款通知的处理规则。
7. 增加浏览器兑换入口。兑换时复核绑定、账号和目标应用，复用 Casdoor 正规会话初始化及账号安全检查；不单独拼接用户名 Cookie，不伪造 LobeHub 回调。
8. 所有跳转只允许配置的 LobeHub 地址及对应应用；凭证响应／兑换禁止缓存，避免凭证进入业务日志及外部 Referer。
9. 联登返回码按更新文档正式返回码表落地，补充参数、签名、解密、账号和凭证错误说明；不顺带改变已有会员维护接口返回码。

### 2.4 LobeHub：免点击 OIDC 入口

1. 增加一个薄的自动登录入口，复用当前 Better Auth 的 `signIn.oauth2({providerId: 'casdoor'})`。保留框架生成的 state、PKCE 和 Cookie，不新增认证系统或手工写 LobeHub 会话。
2. Casdoor 成功兑换凭证后跳到 `/signin/smy`；入口自动发起 OIDC，Casdoor 自动授权后由 Better Auth 正常回调创建本次用户的 LobeHub 会话。
3. 自动入口不能因存在旧 LobeHub 会话而直接返回首页；走“登录”而不是“绑定第三方账号”，保证不会把萨摩耶身份绑定到浏览器原账号。
4. 该入口的新用户、已有用户成功回调均指向固定使用页面；核查首次引导拦截，仅对这条链路做必要适配，不全局关闭引导。
5. 核对对应 Casdoor Application 的实际回调地址、自动登录和授权确认配置，避免出现额外操作页；不放宽禁用、删除、组织归属或其他账号安全限制。
6. LobeHub 原有会员消费及登录后会员刷新保持不变，不能将会员有效作为联登成功条件。

浏览器链路：

`萨摩耶前端自动跳 h5Url → Casdoor 兑换凭证并建立会话 → LobeHub 自动登录入口 → Casdoor OIDC 自动授权 → LobeHub 回调 → 使用页面`

## 3. 实施顺序与交付物

1. **统一身份及数据兼容**：共用查找／建号、手机号索引迁移、会员初始化和重放适配、客服 uniqueId 查询。
2. **Casdoor 联登**：公共协议复用、联登接口、一次性凭证表和浏览器兑换入口。
3. **LobeHub 自动登录**：薄入口、正确账号切换和使用页面落点，核对现有应用配置。
4. **验证与说明**：更新 `docs/smy-membership-api.md`，新增联登接口说明；更新 LobeHub 集成说明。记录请求／响应、配置、错误、账号定位及排查步骤，不写入任何真实密钥。

不修改 Gundam，不调整其他套餐，不改变会员消费缓存，不增加桥接服务、消息队列或新身份平台。

## 4. 验收清单

### 身份与会员兼容

- 同一 `uniqueId` 多次或并发联登只产生一个普通账号、一个绑定；用户没有密码、邮箱、手机号。
- 无手机号／空 userMd5Info／携带不同手机号均能按同一 uniqueId 联登，不改已有联系方式。
- 不同 uniqueId 即使传入相同手机号也不能被自动合并。
- 先联登再开通、先开通再联登均复用同一 Casdoor 身份及同一 LobeHub 用户。
- 老客户的内部用户 ID、历史订单、操作档和订阅保持原样，可继续重放；手机号变化不阻止后续处理。
- 会员 1／3／6／12 月、月底、三种退款时机、退款先到、重复通知、并发、事务回滚及账实异常拒绝继续通过原有回归。
- 客服能按 uniqueId／订单／内部用户 ID 定位，并查询历史会员变化；无会员账号正确显示无操作档。

### 登录与安全

- 验签／解密失败不创建用户或凭证，不返回可用 h5Url。
- 链接未过期可兑换；5 分钟到期、成功使用后、并发重复兑换均不能再次成功。
- 链接生成后账号被禁用或删除，兑换失败；签名请求重放不能绕过单次凭证规则。
- 浏览器未登录、已登录同账号、已登录不同账号三个场景均最终进入本次 uniqueId 对应的 LobeHub 用户。
- 全程无需再次点击、输入密码或确认授权；首次进入也直接进入使用页面。
- 非会员／会员过期仍能完成联登，业务功能由 LobeHub 原有规则控制。
- 失败页面给出明确原因和重新从萨摩耶发起的提示，不回退到旧账号首页。

### 验证方式

- Go 在现有 `_test.go` 文件中补充相关用例，不新建 Go 测试文件；先受影响模块最小测试，再 build／vet 等必要检查。
- 数据库锁、建号和凭证并发测试使用隔离测试库，不用真实用户验证退款或删改会员。
- LobeHub 按仓库规范运行改动范围检查、相关测试及必要类型／构建检查，补充自动登录行为回归。
- 联合登录最终用真实浏览器验证两个站点的 Cookie、自动跳转和账号切换，不能只验证服务端接口成功。

## 5. 配置、上线及回退

- 复用现有萨摩耶商户／密钥配置；新增必要的 Casdoor 公网兑换地址、固定 LobeHub 自动入口及目标应用配置，不允许调用方指定任意跳转目标。
- 实施前核查现有数据库实际索引，备份涉及数据；通过明确迁移移除手机号唯一约束并创建凭证表，不能只改结构标签就假设旧索引已删除。不删历史数据。
- 正式验签联调需要双方商户信息与密钥；前端自动跳转需萨摩耶配合。任何密钥不提交仓库。
- 构建完成后单独执行上线：先部署 LobeHub 自动入口，再迁移并部署 Casdoor，最后开放联登；重启和部署须获得用户指令，不包含在“编写计划”动作中。
- 若回退，先停联登入口；出现多个无手机号绑定后，不能直接恢复旧手机号唯一索引或旧手机号身份逻辑。保留新账号、绑定及全部会员数据，优先关闭新入口并修复，不做破坏性恢复。

## 6. 完成标准

账号与会员统一按 uniqueId 定位；萨摩耶前端自动跳转返回链接后，无额外操作进入正确账号的 LobeHub；一次性凭证及账号限制有效；老会员数据和客服可还原性不受损。提交、推送、部署和重启分别按后续用户指令执行。
